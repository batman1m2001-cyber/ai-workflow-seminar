The same pattern, in production

The meeting-prep assistant is a demo. These run every day on the same engine, and each proves one thing.

Virtual QC

Every collection call is scored for compliance violations and the agent's and customer's tone. Seven checks run in parallel per call; one of them, agent tone, is four layers: cheap gates, a scanner, a decider, a strict re-check that sets the severity.

a failure is never a verdicta model call that can't be parsed raises; the call is recorded as an error, never as “clean”
an eval gates every deploy90 fixture calls against their recorded verdicts; pass means at least 85% match
gate on a rate, not exact matchidentical runs disagree on 6–8 of 90 fixture calls (on a large production batch, about a quarter of results flipped), so the gate is a rate: a healthy run matches about 90–93%
traces without PIIa trace consumer keeps every step and timing, but references the transcript instead of copying it: 1.38 MB to 0.05 MB per call

The callbot

A phone call is one long-lived run fed 8 kHz audio packets: speech detection, transcription, then a turn. The turn runs rules first and calls the LLM only when the rules can't decide (if_(needs_llm)); a script state machine picks the reply; speech synthesis plays it, while a heartbeat runs beside the call.

four bots, one grapheach bot is a prompt file, not new code
per-step overhead matters herea streaming workflow runs steps per audio chunk: this is where the 5× streaming result from Act 5 pays
backpressurea bounded stream edge keeps a slow model from flooding memory during a call

The coding agent

OperonX Studio has Claude Code built in: it reads the project, edits it, runs its services and jobs, and reads its runs. That's an agent in every sense of Act 3: open-ended, high value, slow is fine. And it still runs inside a harness: tools behind permissions, changes checked by the tests and the golden eval, and a human reviewing before anything ships.

The bridge

Meeting prep, QC, the callbot, the coding agent: four systems, one pattern. A workflow, with the model deciding only the steps that need it.
