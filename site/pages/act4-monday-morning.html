Break it, one card at a time

The agent from Act 1 with one more tool, send_email, and no harness. Each card is one Monday-morning event, run for real against the inbox, the web and the model.

Every one of these is silent or total

The attacker's email was sent. The poisoned brief looks fine. One timeout lost two emails. A lead vanished as a “no”. Forty calls were rejected. And nobody can explain any of it.

Harden it by hand: the iceberg

Every wound has a known fix, and none of them is about the model. Add them all and the 15-line agent is 150 lines. The loop is the tip; the execution system underneath is the iceberg: timeouts, retries, failures as values, bounded parallelism, gates, traces, evals, approvals, durable state.

The turn

That list has a name: a workflow engine. LangGraph users already have half of it, because LangGraph is a workflow engine too. That's the point.

The industry reached the same conclusion

The teams building agent frameworks hit the same iceberg, and their answer is the same: agents run inside workflow engines. Even OpenAI retiring its visual Agent Builder points the same way: the workflow doesn't go away, it moves back into code.

So

What should an engine do, which one, and why did we build our own? That's Act 5.
