Chapter 8 · Who picks the next step?

Anthropic's Building effective agents draws the line with one question:

Workflows are systems where LLMs and tools are orchestrated through predefined code paths. Agents are systems where LLMs dynamically direct their own processes and tool usage.

Run Linh's email both ways and count the calls.

The truth

Both are workflows: steps and arrows. The difference is who picks each arrow, your code or the model. That's a property of each arrow, not of a whole system, and most real systems mix both.

The map

Two questions place any system: how fixed is the structure? (left to right) and how much of the work is LLM calls? (bottom to top). Plain code sits bottom-left, a coding agent top-right, and most of what ships lives in between.

Room exercise: click the products under the map one by one. Before each click, ask where it lands.

Not a takedown

The brief's own tool, eval and security harnesses are exactly what a workflow gives you. And its one open-ended box is where an agent, even three in parallel (Chapter 7), really pays.

When should a step be an agent?

Is the path open-ended?you can't write the steps down in advance
Is each run worth a lot?several model calls are cheap next to the outcome
Is the result cheap to check?a person, a test or a rule can tell good from bad
Is slow fine?seconds to minutes, not milliseconds
Is the blast radius small?its tools can't send, pay or delete on their own

Research passes all five: nobody can list in advance which pages matter, a good brief is worth a few calls, sales reads it anyway, nobody waits on it, and its tools only read. Every other box fails at least one, usually the first.

Why the seven agents lose facts

The research, calendar and company agents find the facts: they're in the traces. Then the Memory Agent, an LLM, rewrites everything into one summary, and some facts don't survive: the CRM's pilot history, or the IT manager who actually wrote. A merge written in code can't drop a fact.

Open both in Studio: meeting-prep-brd → on_email, and meeting-prep-operonx → prepare. The same boxes, the same names.

The truth

Agents are real. Use them where the path can't be known, and run them inside a workflow.
