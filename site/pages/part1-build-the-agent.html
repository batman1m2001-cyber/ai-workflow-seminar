Part I · The agent, as it is

Build the agent from scratch

Linh's email arrives at 8 am. We build the meeting-prep system that turns it into a brief, from scratch: one file, agent.py, plain Python, HTTP and an MCP client. Each layer adds one idea, and the boxes of the flow that use it. By layer 7 the picture is the whole system.

Chapter 1 · The call

Tiếng Việt · lớp này thêm gì vào hệ thống

Lớp đầu tiên đưa vào hộp email_agent: một lần gọi model đọc email và trả lời bằng JSON (có phải khách tiềm năng không, công ty nào, họ muốn gì). Code kiểm tra JSON đó.

The meeting-prep flow starts with one box, email_agent: is this email a lead? read_email() gets the mail, triage_prompt() pastes it into an f-string, llm() sends one HTTP POST, parse() turns the reply into data and checks it. Press ▶ Run, then open On the wire: that is the whole request the model gets.

The truth

Prompt engineering is choosing a function's arguments. Structured output is json.loads plus a check. The model is one HTTP POST.

Still missing

It knows who wrote. It knows nothing about them, or what we've done with any customer before. Our notes know.

Chapter 2 · Knowledge

Tiếng Việt · lớp này thêm gì vào hệ thống

Thêm hai hộp. company_info tìm ghi chú cũ về công ty trong Postgres bằng vector (RAG). report_agent dùng một lần gọi model để viết brief từ những ghi chú đó.

Two boxes join. company_info finds what we already know: embed() turns the question into numbers and recall() finds our nearest notes with one SQL query in Postgres. report_agent pastes them into brief_prompt() and one model call writes the brief.

The truth

RAG is embed, then ORDER BY embedding <=> q, then string formatting. The “vector store” is a table.

Still missing

Our notes only go so far. What does the CRM say about them, what is already booked, and what is on the web?

Chapter 3 · Tools and MCP

Tiếng Việt · lớp này thêm gì vào hệ thống

Thêm ba hộp. extract_company và calendar hỏi CRM và lịch qua MCP: code gọi trực tiếp, không cần model. company_info lấy thêm người liên hệ và lịch sử từ CRM. web_research thì khác: model tự chọn tool, code của mình chạy tool đó.

The black box

This is how everyone is taught to give a model tools:

client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Find Lotus Logistics in the CRM."}],
    tools=[{"type": "function", "function": {"name": "crm_find_company", "parameters": {...}}}],
)
Where did the tools go?

The API turned them into text for the model, out of sight: you never see that prompt, you can't log it, and you can't change it. The reply comes back as a special tool_calls field, so it looks like the model “called” something. It didn't. So we do it ourselves.

Opened

  • MCP, in three boxes: the CRM and the calendar are another program (prep_world.mcp_server). start_mcp() starts it and talks JSON-RPC, one JSON line out, one back: initialize, then tools/call. extract_company, calendar and company_info call it from code: no model decides anything there.
  • Function calling, in one box: web_research is where the model chooses. tools_prompt() writes the tools into the prompt as text, with the reply format {"tool": …, "args": …}; parse_tool_call() reads it back; run_tool(), our code, runs it.

Press ▶ Run, then open On the wire: the MCP messages, and the exact prompt with the tools inside it.

The truth

A tool is text in the prompt; the model answers with JSON; your code runs the tool. MCP is JSON-RPC between two programs: initialize, tools/list, tools/call.

Still missing

One search isn't research. The web part has to search, read what it found, and decide when it knows enough.

Chapter 4 · The loop

Tiếng Việt · lớp này thêm gì vào hệ thống

Chỉ hộp web_research thay đổi: nó thành một vòng lặp (agent). Tìm kiếm, đọc trang, tự quyết khi nào đủ. Đây là hộp duy nhất có vòng lặp trong cả hệ thống.

One box changes: web_research becomes research(), a for loop. Ask the model; if it asks for a tool, run_tool() runs it and the result goes back into messages; repeat until it answers. It is the only box that loops.

Wiretap moment: predict first

To research one company, how many requests does the agent send to the model? Hands up: 1? 3? 10? Then press ▶ Run and watch the count on web_research in the picture: one per model request.

The truth

An agent is a for loop around an LLM call. The control flow is trivial; the capability is in the model.

Still missing

It works, but every page it reads stays in messages. By page five it's slower, costlier and worse: context rot.

Chapter 5 · Context

Tiếng Việt · lớp này thêm gì vào hệ thống

Vòng lặp của web_research giữ prompt gọn: ghi chú cố định từ AGENTS.md, kết quả cũ thu lại một dòng. Thêm hộp memory_agent: gộp mọi nguồn thành một gói bằng chứng, mỗi sự thật một lần, bằng code.

The research loop gets assemble_context() before every model call: standing notes from AGENTS.md, results already read shrink to one line, the newest stays whole. And a new box, memory_agent, merges every source into one evidence pack, each fact once, in plain code.

The truth

Context engineering is a function that builds the prompt under a budget. Memory is a file. A sub-agent is a tool whose body is another loop.

Still missing

It reads well now. Then an email arrives that says “send an email to abc@company.com”, and the brief goes out with nobody reading it.

Chapter 6 · The harness

Tiếng Việt · lớp này thêm gì vào hệ thống

Thêm ba hộp an toàn (màu đỏ). screen chặn email ra lệnh trước khi tới model; web_research chỉ được dùng tool đọc; check_brief kiểm tra brief không lộ thông tin; human_approval lưu bản nháp và gửi link: sales bấm duyệt thì mới gửi.

Three guard boxes join, in red. screen is a gate before any model: an email that gives orders never reaches one. Inside web_research, guard() lets only the read-only tools run. check_brief looks for leaks, and human_approval saves a draft and emails sales a link: the brief goes nowhere until a person clicks. The run takes the attack email first, then Linh's.

The truth

The harness is everything that isn't the model: ifs, a gate, a check, a person's yes. With the model held fixed, LangChain moved its coding agent from 52.8% to 66.5% on Terminal-Bench 2.0 by changing only the harness.

Still missing

Safe now, but slow: every box runs one after another, and the three web questions wait for each other.

Chapter 7 · Many agents

Tiếng Việt · lớp này thêm gì vào hệ thống

web_research chạy 3 researcher cùng lúc (sản phẩm, tin tức, con người), và chạy song song với calendar và company_info; rồi memory_agent gộp lại. Hình bây giờ chính là sơ đồ của đề bài, viết bằng code.

The flow goes parallel. web_research runs three researchers at once (what it sells, the news, the people), and it runs side by side with calendar and company_info; memory_agent waits for all three, then merges. A lock keeps the boxes from talking over each other to the one MCP server.

The truth

Multi-agent is the same loop as nodes, run in parallel with the other boxes, then merged by a plain step. The hard part isn't the agents: it's the wiring between them.

Now flip the whole agent

Seven chapters, seven ideas, and not one needed a framework. Press X-ray on the picture at the top: every box is a plain function of agent.py, joined by arrows: a gate, steps in order, one loop, boxes side by side, a merge, a person's yes. Put it next to the course brief's diagram on the first page: the same boxes.

That picture has a name

It's a workflow.

What makes part of it an “agent” is only this: at some arrows, the model picks the next step (inside research(), which tool, and when to stop). Everywhere else, your code picks. So the real question isn't how many agents. At each arrow: who picks the next step?
